# 固定地图定位稳定性验收（第一轮）

## 目标与现状

巡检“地点”首先是地图坐标系 `W` 中的 `xyz` 或 `T_WI` 位姿。本轮先用现有离线工具检验：给定**同一张历史地图**和近似初值，选定轨迹的点云在重复配准与局部动态遮挡下能否稳定地落在相同位置，并记录配准耗时。设备、缺陷识别不在本轮范围。

当前 `MainPipeline::process_measure_group` 在每个跟踪帧后调用 `self.map.insert(map_points)`，所以完整 replay 不是固定地图定位。不过 `scripts/revisit_packages.py` 已能把历史 surfel/关键帧作为目标，用多尺度局部配准后访点云，再用虚拟视图检查 range agreement、free-space violation、overlap 和点面残差；`fastlio-loop` 也有独立的局部 ICP。脚本把配准函数命名为 `gicp`，但其残差与求解实际是点到平面 ICP，并非使用两侧协方差的广义 ICP。**第一轮复用这条离线链路，不要求先实现在线 localization 模式。**

## 一个主要开发任务

由人类开发者设计并实现最小的**离线固定地图定位探针**，扩展现有回访脚本或独立调用已有配准函数。输入为首访的历史关键帧/地图、后访的一段关键帧点云、每帧近似初值与固定种子的点云扰动；输出为每帧配准位姿、成功/拒绝原因、有效对应数、虚拟视图指标、配准计算耗时和扰动统计。历史目标必须在整个测试中保持相同，不能把后访点加入目标地图。

先做**已知近似初值的逐帧局部配准**，再看连续后访帧的位姿是否平稳。它能评估历史地图的可定位性和配准对干扰的鲁棒性；单帧 GICP 的结果不能直接代表连续 IEKF 跟踪、全局重定位或闭环后的绝对精度。

## 数据切分

1. 优先用 `corridor_04` 的首访关键帧/历史地图、后访关键帧作测试；它有真正的同房间回访及既有诊断包。用 Spires 的首访/后访作第二个场景，覆盖大地图和较高关联开销。冻结地图时须按固定的**首访截止时间**筛选，不沿用当前诊断脚本的 `created_time < 当前帧时间 - 30 s` 规则；后者会让后访期间新建的 surfel 进入目标。
2. `KA_Urban_East` 目前没有紧回访，适合做相似结构的失败或误配案例，不能充当同地点正例。其他 bag 只有在确认首访/后访几何重叠后纳入。
3. 固定数据集片段、时间边界、配置、地图快照、初始状态、机器与随机种子。所有方案使用同一套输入；开发段选扰动强度，测试段只用于最终对比。

## 扰动阶梯

第一轮的关键帧是已经 deskew 的**世界系点云**：导出时使用 `p_W = R_WI (R_IL p_L + t_IL) + p_WI`。应按这个公式逆变换回关键帧末端的 LiDAR 坐标，注入扰动，再变回世界系供现有配准使用；不能只对 `T_WI` 求逆后把所得 IMU 坐标误当成 LiDAR 坐标。此法只验证**配准阶段**，不验证原始逐点时间、deskew 或 IMU。每个等级跑多个固定种子，保存实际修改的点数和比例。

1. 无扰动重复回放：先检查确定性、状态初始化和固定地图行为。
2. 点缺失：模拟近处行人遮挡，让其后方的原始射线回波消失；不要只向干净点云无条件加点。
3. 移动目标：在连续帧中添加空间和时间连续的人形/紧凑目标回波，并遮挡对应背景点；设定少量、中等、高覆盖率。目标随时间运动，不能每帧独立随机撒点。
4. 独立的测距噪声与稀疏化：沿传感器射线方向扰动距离或丢点；不直接对世界坐标加独立高斯噪声。由于关键帧已经去畸变，这只能近似量测扰动，不能宣称还原了真实行人逐点遮挡过程。

扰动区域不能只选开阔处；至少包含一段走廊或单平面退化区、一段转弯、一次静止或低速区（若数据确有该行为）。

## 指标与解释

| 指标 | 口径 |
|---|---|
| 位置/姿态重复性 | 同一关键帧受扰配准位姿相对干净配准位姿的 `W` 系平移差和 SO(3) 角差，报告 median/p95/max；连续帧再报告位姿跳变。这是**抗扰一致性**，不是绝对精度。 |
| 绝对或相对误差 | 有独立参考时报告 ATE、固定间隔 RPE；Spires 的 HBA/VILENS/COLMAP 轨迹同源，按弱参考报告。没有独立参考时不宣称绝对精度。 |
| 稳定性 | GICP 拒绝比例、连续拒绝最长时长、异常位姿跳变、有效对应数，以及虚拟视图的 overlap/range agreement/free-space violation。低残差但错误位姿仍算失败；跳变阈值须结合运动上界在开发段预先确定。 |
| 速度 | 在固定硬件下分别报告**配准求解** p50/p95/p99 和含目标构建、扰动、虚拟视图评估的离线总耗时 p95。Python 诊断脚本的 p95 不等同于未来 Rust 在线定位延迟；如改用 Rust ICP，须单独记录版本与硬件。 |
| 地图约束 | 所有样本使用同一个首访截止时间及目标地图，记录地图点数和文件哈希；后访关键帧不得进入目标。 |

第一轮同时输出每个扰动等级相对无扰动基线的变化量和最坏种子。不得只报跨种子平均值，也不得通过放宽观测阈值或删除失败帧改善数字。

## 最低验收

- 历史地图按固定首访截止时间冻结；测试时间段的 surfel/关键帧不进入目标。
- 同一无扰动输入、同一初值重复配准，位姿和统计在声明的确定性范围内一致。
- 扰动生成器有测试证明射线方向、遮挡逻辑与随机种子可复现；关键帧的时间戳不变。
- 配准耗时 p95 以全部受测帧为分母，拒绝帧计入耗时和失败率，不能从结果中删除。
- 报告清楚区分“逐帧配准抗扰性”“连续跟踪”和“跨次巡检”；本轮只验收第一项。

人类实现前需说明：关键帧导出的点所属坐标系、首访截止时间怎样确定、后访每帧初值怎样产生、虚拟视图是否参与候选选择，以及配准耗时的计时边界。若虚拟视图参与选解，不得再把同一指标当作独立成功证据；应保留独立参考或留出证据做验证。

## 首轮试跑（2026-11-23，探索性结果）

`scripts/frozen_map_probe.py` 从 `corridor_04` 前 18 个关键帧构造固定目标（体素 0.3 m，9447 点），测试后访关键帧 252–274。三个种子 41/42/43，每个种子跑干净输入、移动角域遮挡和测距噪声加 20% 随机丢点。目标点与法向的哈希在三次运行中一致：`a623b9dc6d9770c4ea8fa40f17d8c430b2a1bafe2b29cd8cad5584c3a6ac77ec`。使用 Open3D 0.20.0 的点到平面 ICP、Huber 0.05；不是仓库主流水线的 IEKF。已有修正轨迹只用于提供相同的近似初值，不能当独立真值。

```bash
OMP_NUM_THREADS=4 output/venv/bin/python -B scripts/frozen_map_probe.py \
  --start-frame 252 --end-frame 275 --seed 41 \
  --out output/frozen_map_probe_252_seed41.json
```

在 AMD Ryzen 9 9950X3D 上，以下 p95 由每类 23 帧 × 3 种子 = 69 次求解得到；相同 23 帧重复出现，不能视为 69 个独立地点。`sample total` 只含单帧扰动、配准和虚拟视图评估，不含目标地图构建与文件读取。

| 条件 | 求解 p95 | 单样本总耗时 p95 | 配对位移 p95 | 配对旋转 p95 | 虚拟视图 range agreement 均值 |
|---|---:|---:|---:|---:|---:|
| 干净 | 4.33 ms | 4.90 ms | 基线 | 基线 | 0.546 |
| 移动遮挡（平均替换 9.1% 回波） | 4.76 ms | 6.41 ms | 0.052 m | 0.225° | 0.490 |
| 测距噪声 0.03 m + 随机丢点 20.0% | 4.10 ms | 4.80 ms | 0.022 m | 0.146° | 0.543 |

此处“配对”是与**同一帧、同一初值**的干净配准位姿相比。三种条件的最低 ICP fitness 分别为 0.614、0.614、0.605；低 fitness 的早期后访帧不能按“成功定位”计，当前还没有冻结接受阈值。用种子 41 额外测试初值平移 `+0.5 m`、yaw `+5°` 后，干净帧最终位姿相对零偏差初值结果的平移差 p95 为 0.002 m、最大 0.041 m；这只说明本片段的局部收敛域覆盖该扰动。移动遮挡的几何模型是随帧移动的角域近回波替换，尚非真实人体扫描；前 23 帧中有一帧未命中该角域。虚拟视图和配准目标均来自同一历史点云，所以 range agreement 只是内部一致性诊断。下一轮应加入更大初值偏差、退化段，并用独立证据核对结果。

试跑产物：`output/frozen_map_probe_252_seed{41,42,43}.json` 与 `output/frozen_map_probe_252_shifted_seed41.json`（本地忽略文件）。扰动几何的两项单元测试可用 `OMP_NUM_THREADS=4 output/venv/bin/python -B -m unittest scripts.test_frozen_map_probe -v` 运行。
